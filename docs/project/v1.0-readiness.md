# v1.0 Stable Specification Readiness

This page records the repository-controlled evidence used to promote ONDTF from v0.9.0 Candidate Specification to **v1.0.0 Stable Framework Specification**.

## Release conclusion

**ONDTF v1.0.0 is released as a stable specification baseline.**

All **nine of nine repository-controlled gates** were satisfied before promotion. The stable contract adopts the frozen v0.9.0 candidate normative semantics without material semantic change.

| Gate | State |
|---|---|
| Normative stability | satisfied |
| Identifier stability | satisfied |
| Requirement/conformance traceability | satisfied |
| Deterministic validation | satisfied |
| Adversarial/negative evidence | satisfied |
| Compatibility/change control | satisfied |
| Errata process | satisfied |
| Blocking-issue disposition | satisfied |
| Release integrity | satisfied |

## Evidence boundary

ONDTF remains at **E1 — repository-controlled reference/executable evidence**. Stable status does **not** assert independent implementation (E2), cross-implementation interoperability (E3), operational deployment (E4), production readiness, certification, or legal/regulatory approval.

Issue #24 remains bounded platform-security evidence-required work. Its unresolved state is not interpreted as PASS and does not invalidate the stable specification contract.

## Stable maintenance

Material normative change after v1.0.0 is governed by `governance/v1.x-change-control.yaml`, `governance/errata-and-emergency-change.yaml`, and evidence-invalidation/reassessment rules. Breaking change is not permitted inside the v1 line.

The historical readiness register remains executable evidence of the promotion decision and should not be rewritten to imply stronger external evidence.
