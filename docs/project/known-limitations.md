# Known limitations

v1.0.0 is a **stable specification**, not a claim that every external adoption or evidence layer is mature.

| ID | Stable-release limitation | Treatment |
|---|---|---|
| LIM-01 | Independent implementation evidence is not yet available | current evidence remains E1; E2 is not claimed |
| LIM-02 | Standards mappings do not create adoption authority | formal selection remains profile-governed |
| LIM-03 | Jurisdiction profiles are not legal advice | competent current review remains required |
| LIM-04 | Quantitative defaults are contextual | provisional values retain recalibration triggers |
| LIM-05 | Reference code is not production software | conformance targets observable behaviour, not reference internals |
| LIM-06 | Recognition depends on external authority | illustrative profiles create no legal recognition |
| LIM-07 | Protocol/cryptographic choices remain profile-dependent | technology neutrality is retained |
| LIM-08 | Repository validation is not provider certification | qualified conformance claims remain required |
| LIM-09 | External standards and dependencies change | dependency/change-impact governance remains active |
| LIM-10 | GitHub-hosted security-setting evidence is incomplete | issue #24 remains evidence-required without affecting the stable specification claim |

See [Specification Maturity and Evidence Governance](maturity-and-evidence.md) and [v1.0 Stable Specification Readiness](v1.0-readiness.md).
