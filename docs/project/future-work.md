# Future work after v1.0.0

The stable specification deliberately stops broad conceptual expansion. The highest-value next work is empirical adoption evidence.

Priority work:

1. obtain an independently operated implementation or profile-construction exercise capable of supporting E2 evidence;
2. run that exercise from the published v1.0.0 material with clarification requests recorded rather than resolved through undocumented maintainer guidance;
3. disposition ambiguities, implementation defects and adoption friction through normal v1.x change control;
4. obtain competent jurisdiction/sector review for any profile represented as reviewed or adopted;
5. collect stronger interoperability, operational, assurance, accessibility and remedy evidence without manufacturing it from repository-local simulations.

The adopter front door and starter package added with v1.0.0 should be treated as instruments for this evidence programme, not as reasons to introduce a new normative layer.

A v1.x change should answer a demonstrated adopter, implementation, conformance, assurance or maintenance need. Evidence maturity remains independent of specification version.
